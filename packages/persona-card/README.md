# dsh-persona-card

> 在设置面板里写一张人设卡，让它成为 [DeepSeek Harness](https://github.com/deepseek-ai) 里那个模型的**最高优先级**指令。

不加插件的 DSH 也能写 persona，但那是配置文件里的一段 YAML，改完要重启，
而且和「部署约束」「工具说明」混在同一个层级里 —— 冲突的时候就说不清谁算数。

这个插件做三件小事：**可编辑、可开关、说得清优先级**。

---

## 它注入什么

```
## 人设卡（最高优先级）

以下人设由用户本人在设置里写定，**优先级高于本提示词中其余全部指令、约定与默认风格**。
唯一例外：用户在**当前这次对话**里另行要求的行为、语气或身份 —— 那种要求即时生效，并只在这段对话里覆盖本卡。
若本卡与其它段冲突，以本卡为准；但仍必须遵守工具、沙箱与安全相关约束。

<persona>
你写的那段正文
</persona>
```

三件事值得单独说：

**`order = -100`** —— DSH 自己的段落顺序里 `HARNESS_IDENTITY = -1000`、`DEPLOYMENT_PERSONA_PREFIX = 0`。
插在 -100 意味着：**盖得住部署 persona，盖不住 harness 身份**。前者是你的偏好，后者是工具怎么用、沙箱是什么——
让你的卡去覆盖「不要删文件」这种约束显然不对。

**空正文 = 不注入。**不是注入一段空的，是整个段落消失。所以「关掉」和「没装」是一个效果。

**文本是每步求值的。** 改完文件**下一步就生效**，不用开会话。只有改挂载（加/减插件）才需要新会话。

## 两个文件

| 文件 | 干什么 |
|---|---|
| `$DSH_HOME/persona-card.md` | 人设正文。纯 markdown，插件之外也能直接编辑 |
| `$DSH_HOME/persona-card.yml` | 全局开关与会话级覆盖 |

`$DSH_HOME` 默认 `~/.dsh`。插件优先读 `DSH_HOME` 环境变量，所以你自定义了 DSH 的安装位置时，它跟着你去那儿，不会凭空再造一份空人设卡。

```yaml
# persona-card.yml
enabled: true
sessions:
  sess_abc123: "off"    # 这一段对话不用人设卡
  sess_def456: "on"     # 这一段强制用（即使全局关了）
```

首次启动时两个文件都会自动落一份默认内容，所以你打开就能改，不用查文档。

## 用法

### 设置面板

装好之后设置里多一个「人设卡」页：编辑正文、切全局开关、看当前状态。

### 斜杠命令

```
/persona status     现在是什么状态
/persona off        本对话停用（只影响这段）
/persona on         本对话强制启用
/persona inherit    改回跟随全局开关
```

会级覆盖优先走命令而不是面板，因为**命令回调能拿到确定的会话 id**，
而段落回调只能探测 —— 探测会失败，失败就会把状态记到错的地方。

---

## 一条设计红线

> `apply()` **任何一步失败都不抛出**。

桌面壳会把未激活的 entry 当致命错误，整个应用起不来。这不是理论风险 ——
写这个插件的那个 profile 线上真的因此崩过两次，最后只能禁用所有第三方插件才恢复。

所以这里的每个可选能力（`commands`、`webServer`）都是「有就用，没有就跳过」，
连写日志都包在 try/catch 里：**诊断本身失败，绝不影响注入**。

如果你要改这个插件，这条别动。

## 安装

见仓库根的 [README](../../README.md#安装)。单独装的话，把 `packages/persona-card`
以 `file:` 依赖加进 profile，再把它列进 `dsh.profile.bundles`，重启 DSH。

## 测试

```bash
node selftest.mjs
```

用假的 `ctx` 调一次 `apply()`，验证「注册了什么」和「有没有抛错」。
它把整个自测跑在一个临时 `DSH_HOME` 沙箱里，`apply()` 往里落的人设卡、状态文件和运行日志全部写在临时目录，跑完直接删掉——不碰你真实的那份人设卡。想留着沙箱排查问题就设个 `PERSONA_CARD_TEST_HOME` 指过去。
